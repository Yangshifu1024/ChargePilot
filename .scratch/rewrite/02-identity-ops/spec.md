# 阶段 02 · 身份与后台

Status: ready-for-agent

## Problem Statement

没有任何身份能力：C 端用户无法登录，后台管理员无法登录，权限、审计、MFA、公告、仪表盘全部缺失。所有后续阶段的 API 都没有鉴权可用。

## Solution

交付 identity 域（C 端登录/会话/手机号）与 ops 域（后台账号/角色/权限/数据范围/字段掩码/MFA/审计/公告/仪表盘）的全量路由与真库验证，使后续阶段直接复用鉴权中间件与后台框架。

## User Stories

1. 作为充电用户，我想用 development 模式一键登录换取访问令牌与刷新令牌，所以开发环境不需要真实微信。
2. 作为充电用户，我想用微信 code 换取会话（jscode2session）与授权手机号，所以生产联调路径就绪（真实 appid 在上线前清单验证）。
3. 作为充电用户，我的访问令牌过期时客户端能用刷新令牌静默换取新令牌，且旧刷新令牌轮换后仍可在宽限期旧摘要列表中识别，所以登录态既安全又不断。
4. 作为充电用户，我想注销会话使全部已发令牌失效，所以换设备/丢手机时不被冒用。
5. 作为运营人员，我想用用户名密码 + TOTP 两步验证登录后台，所以单凭泄露的密码进不来。
6. 作为运营人员，我想被分配角色并获得权限与数据范围（站点/区域限定），所以只能看到和操作职责内的数据。
7. 作为运营人员，我的敏感字段输出受字段掩码约束（按角色），所以手机号等隐私不全量裸奔。
8. 作为运营人员，我想在后台查看审计日志（谁在何时改了什么），所以有操作追责依据。
9. 作为运营人员，我想管理后台账号（创建/停用/重置密码/分配角色），所以人员变动即时生效。
10. 作为运营人员，我想发布公告并在 C 端展示，所以能触达用户。
11. 作为运营人员，我想看运营仪表盘（日活跃、收入趋势等日界投影），所以不用手工汇总。
12. 作为开发者，我想后台登录有 IP 频次限制、MFA 绑定有租锁与频次限制，所以暴力破解与并发绑定被挡住。

## Implementation Decisions

- 会话模型照搬旧版语义：访问令牌 JWT（user 15min / admin 8h，双 kind）、刷新令牌 `RT_/ART_ + sid.secret`、Redis Lua 轮换保留 ≤32 个旧摘要、KEEPTTL 不延长绝对寿命（7 天）。
- 微信登录：reqwest 直调 jscode2session 与手机号接口；`LOGIN_MODE=development` 时走开发换购器。真实微信凭据验证列入上线前清单，本阶段以 development + 模拟应答覆盖 wechat 路径的单元/集成测试。
- MFA：TOTP 绑定流程（enrol→confirm→disable，5 分钟窗口）、挑战态存 Redis（5 分钟）、租锁 SETNX + 频次 INCR（Lua 原样移植）。
- RBAC：role / permission / role_permission / admin_data_scope / admin_field_mask 五表语义照旧（字段掩码是活功能，保留层）。
- 审计：事务内写入（与业务变更同事务提交）。
- 路由前缀：C 端 `/api/v1/user/auth|profile`，后台 `/api/v1/admin/auth|accounts|roles|ops`；鉴权中间件在本阶段定形供后续阶段复用。
- 引导账号：`ADMIN_BOOTSTRAP_*` 启动时确保存在，密码 bcrypt 哈希。

## Testing Decisions

- 主缝真库 + 真实 Redis 集成：登录→MFA→鉴权→审计全链路；会话轮换（旧摘要识别、注销后全部失效）；频次限制触发与恢复。
- 刷新令牌并发使用（旧令牌重放）的拒绝行为有专项测试。
- 数据范围：受限管理员越权访问他域数据返回 2xxx 错误。
- 不 mock Redis 或数据库；密码学能力在阶段 01 已测，本阶段只测流程行为。

## Out of Scope

微信支付（阶段 04）；后台任何业务数据页面（属于 03–05 各域）；真实微信凭据联调（上线前清单）。

## Further Notes

本阶段是后续所有阶段的鉴权前置；鉴权中间件的行为测试在本阶段固化，后续阶段不再重复测试中间件本身。

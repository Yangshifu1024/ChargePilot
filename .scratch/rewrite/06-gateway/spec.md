# 阶段 06 · 设备网关

Status: ready-for-agent

## Problem Statement

设备接入能力缺失：DC589 TCP 协议、连接治理、遥测管道、远程启停、刷卡、故障上报都没有；容量设计（G1–G4）尚未落地为代码。

## Solution

交付 gateway-runtime：帧层黄金样本驱动的 DC589 实现 + 容量预算导出的连接治理与批量遥测管道 + 停机重试/补偿的进程内化；与阶段 03 的开通桥接、阶段 04 的状态机事件全面接通。

## User Stories

1. 作为设备（桩），我上电后按协议注册（A0 重试），注册成功即进入心跳节奏（空闲 60s），所以即插即用。
2. 作为设备，我充电中的心跳周期被平台切换为 15 秒并可能附带端口数据，所以数据实时。
3. 作为设备，我收到远程启动/停止命令并按协议应答，命令超时未达时平台自动重试，所以控制可靠。
4. 作为设备，我本地启动（投币/离线卡/按键）后上报（B4），平台补全订单，所以离线操作不丢单。
5. 作为设备，我上报在线卡刷卡（B6），平台实时校验并下发授权或拒绝，所以余额风控在刷卡的瞬间生效。
6. 作为设备，我上报故障/传感器事件（C0），平台转为故障工单与告警，所以隐患被看见。
7. 作为设备，我的旧连接在重新注册时被踢除，所以断线重连不会产生双会话。
8. 作为充电用户，我充电页的实时电量/功率/估费来自会话内存快照（毫秒级），所以数据即时且不受数据库抖动影响。
9. 作为运维者，我想在发布重启后 60 秒内看到全部设备重新上线，所以发布窗口的设备断连可控。
10. 作为运维者，我想看到批量缓冲深度与丢弃计数指标，所以写入管道健康可观测。
11. 作为运营人员，我想让已导入设备上线后自动完成开通同步（消费阶段 03 的待同步标记），所以导入即接入。

## Implementation Decisions

- **帧层（辅缝 1）**：`SOP|LEN|CMD|SESSION(6B)|DATA|SUM(异或)` 编解码纯函数；36 条平台指令与 28 项本地参数按协议文档实现；BCD、小端、单位换算（分 → 协议余额单位）封闭在 `protocol-dc589`，业务代码零协议字面量（红线层：`0xBB` 等不出现）。
- **连接治理（G1）**：每连接独立 task；读超时 90s；同设备互踢（会话表原子替换）；accept 限速 200/秒；半开连接由读超时回收。
- **遥测管道（G2）**：帧到达先更新会话原子快照（实时读数据源），再入有界缓冲（4096）；批量 task 200ms/500 条多值 INSERT；聚合 UPSERT 同批合并；缓冲满丢最旧明细并计数（分级语义见 [ADR 005](../../../docs/adr/005-capacity-boundary.md)）；快照缺失时实时读回退查库。
- **命令队列（G3）**：每会话有界 mpsc（深度 16）；失败落命令表 `next_retry_at` 退避；停机重试（用户停止 5s 重试）与启动补偿进程内化，替代旧版跨进程补偿对。
- **事件接通**：设备帧 → `domain_event`（同事务）→ 状态机推进；刷卡事件 → 准入判定 → 授权/拒绝下发；故障事件 → 告警同步（消费阶段 03 告警域）。
- **优雅停机**：停 accept → 冲刷遥测缓冲 → 等待在途帧与批量落库 → 关池；顺序可测试。

## Testing Decisions

- 黄金样本（辅缝 1）：协议文档示例帧逐条建样（含 12 路以上双包、BCD、跨端口数据），编解码互逆断言。
- 主缝真库集成：模拟器单台闭环（注册→扫码下单→启动→计量→停止→结束→结算联动阶段 04）；刷卡准入与拒绝码；本地启动补单；故障转告警。
- G2 分级：缓冲满时明细丢失而快照/聚合完好，丢弃计数递增；崩溃窗口 ≤200ms 有注入测试。
- 互踢与读超时：双连接注册、静默连接回收的断言。
- 辅缝 3：优雅停机顺序与重启恢复（批量模拟器小规模即可，全量在阶段 07/10）。

## Out of Scope

2000/1000 全量压测（阶段 07/10）；OTA 指令（协议含 6 条，旧版未实现，维持不做）；监管上报。

## Further Notes

本阶段是与「红线层」接触面最大的阶段；协议语义存疑时以协议文档与旧版实现双重对照，差异记 ADR 修订记录。

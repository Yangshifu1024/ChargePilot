# 阶段 05 · 营销与导出

Status: ready-for-agent

## Problem Statement

营销能力（优惠券、活动规则、核销）与批量导出缺失；订单计价的券抵扣接缝（阶段 04 预留）尚未接入。

## Solution

交付 marketing 域（券/活动/发放/核销/优惠计算）与 export 域（任务、Excel 生成、下载、清理循环），并把券规则接入订单计价。

## User Stories

1. 作为运营人员，我想创建优惠券（满减/折扣、有效期、发放量），所以能做拉新与召回。
2. 作为运营人员，我想配置活动规则（条件赠券、幂等发放），所以活动自动化不重复发券。
3. 作为充电用户，我想查看我的券与可领的券，所以知道有什么优惠。
4. 作为充电用户，我想在充电订单结算时自动使用最优券抵扣，所以不用手动计算。
5. 作为充电用户，我想刷卡/扫码时看到券的适用性提示，所以不会被意外扣全价。
6. 作为运营人员，我想看到券的核销统计，所以活动效果可评估。
7. 作为运营人员，我想把订单、账单、用户等列表批量导出为 Excel（异步任务、完成通知、下载），所以大数据量不走页面分页。
8. 作为运营人员，我想让过期导出文件自动清理（每小时循环、每批有上限），所以存储不被拖垮。
9. 作为开发者，我想优惠计算以分单位精确（decimal 中间计算、边界取整可预期），所以不出现分位误差。

## Implementation Decisions

- 券规则接入阶段 04 预留的计价接缝：优惠计算为纯函数（domain 层），输入订单金额快照 + 券规则，输出抵扣拆分；同事务写核销记录（`coupon_redemption`）与幂等发放（`coupon_grant_request`）。
- 活动求值：条件命中 + 幂等发放编排照搬旧版语义；审计事务与准入校验保留。
- export：任务表（状态机：受理→生成→完成/失败）、生成走受管理事务与文件发布、下载走资源归属校验（数据范围约束）、清理循环为每小时受管理 task（每批 ≤1000，语义照搬）。
- Excel 生成用 rust_xlsxwriter，输出格式对齐旧版列结构（消费审计表核定）。
- 券与订单计费的组合点做差分对照（与旧版同输入）。

## Testing Decisions

- 主缝真库集成：建券→发放→下单→核销全链路；重复发放幂等；过期券不参与计算；核销与结算同事务（回滚即不核销）。
- 差分对照（辅缝 2）：优惠计算纯函数（满减阈值边界、折扣取整、叠加规则）。
- export：生成→下载→清理生命周期；并发导出的任务隔离；文件归属（受限管理员拿不到范围外导出）。
- Excel 输出以「生成文件可被标准库打开且行列数正确」断言，不比对字节。

## Out of Scope

营销短信/推送触达（旧版亦无）；导出格式新增（仅对齐旧版列结构）。

## Further Notes

优惠计算若与旧版差分出现分歧，处理原则同阶段 04：以差分为准，记 ADR 修订记录。

# 02: 契约缝基座——路由清单与信封对照（S0）

**What to build:** 为后续大规模重排建立唯一新增的测试缝：契约缝。手写维护全量路由清单常量（方法 + 路径），对每条发探测请求断言——已知路径配错方法得 405、未知路径得 404 信封（服务回落返回未提供信封，区分度成立；契约测试以「无静态目录」模式构建路由，不挂 SPA 回落）。另按业务域选取每域 admin/user 各至少一个代表响应 DTO，做信封字段序列化对照（字段基线提炼自现有集成测试已逐字段断言的集合，清单以注释钉在测试头部）。纯进程内无外部 IO，纳入日常检查。

**Blocked by:** None (can start immediately)

Status: ready-for-agent

- [ ] 路由清单常量与全部路由注册函数人工对齐一次，含绕过总装配直接合并路由的测试装配路径（或将其改回统一装配）
- [ ] 探测式断言覆盖每条清单项：错方法 405 / 未知路径 404 信封，双向成立
- [ ] 每域至少一个 admin 门面代表 DTO 与一个 user 门面代表 DTO 的序列化对照，字段名/类型/空值形态逐项断言
- [ ] 与既有「前端调用 ↔ 后端路由」对账脚本的分工写入测试头部注释（本缝管路由集合与信封形状不变，脚本管前后端一致）
- [ ] 日常检查（不含真库变量）即可完整执行本缝全部测试

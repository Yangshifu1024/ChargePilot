## 三、验收结果（全部达标）

**功能五项**：契约/schema 一致（85 表=设计稿）；差分对照 120 条黄金样本全绿；资金真库集成 145 用例 0 失败；E2E 闭环（真库全链 + compose 冒烟 18/18）；打包形态。

**容量四项**（compose 生产栈实测，复现命令在验收报告）：
1. 2000 连接稳定 30 分钟：注册 100%、收发 157 万帧平衡、**零断线**，内存 **62–79MiB**（阈值 512MB）
2. 1000 并发充电遥测端到端 **p99 = 345ms**（阈值 1s，帧采集→落库实测）
3. 进程重启后 **22 秒**全部 2000 台恢复在线（阈值 60s）
4. 对账恒等式成立（received=flushed+dropped）、聚合与明细逐条相等、超载丢弃线性可解释

**真库测试**：`set -a && source backend/.env && set +a && cd backend && cargo test --workspace` → 145 通过 0 失败（真实 MySQL 8.4）。

## 四、借重写完成的设计优化（非照搬）

1. **五服务合一体**：多进程 HTTP 编排（central 内部端点/worker 扫描/gateway 接入）改为单进程内事件驱动 + 进程内命令通道，去掉服务间 HTTP 与三库拆分（ADR 001/002）。
2. **旧版缺口补齐**：paid 态启动超时兜底（旧版缺口）、B9 停止无回执观测、扫框架统一节拍/滞后指标/内存态诊断接口（ADR 002 红线：扫描器幂等）。
3. **遥测分级语义落地**：有界缓冲丢最旧+计数可解释，快照/聚合零丢失（ADR 005），聚合 UPSERT 多值化后单机 1292 样本/s（真实负载 9.7 倍余量）。
4. **环境变量冻结**：22 个清单+启动 WARN，配置漂移有据可查（旧版 caarlos0/env 无清单约束）。
5. **验收资产可复现**：黄金样本差分（旧版 Go 计费纯函数产出 120 条）、compose 冒烟一条命令、容量四项 SQL/命令全部落文档。
6. **修复的旧版生产缺陷**：启动回执漏写端口占用（active_port_charge）、注册表互踢 close future 被丢弃、切片越界类（Go 安全切片语义在 Rust 的对应处理）、导入设备端口外键写错等——每处随对应阶段提交注明。

## 六、剩余风险（已在验收报告登记）

- **OrbStack 容器网络空闲回收**：容器间 60s 空闲 TCP 被虚拟网络层回收（本机直连对照零断线证明非服务端缺陷）；真实部署不受影响。
- **15x 超载丢样**：仅模拟放大口径出现；真实负载（133 样本/s）有 9.7 倍余量。若未来逼近瓶颈，优化方向已归因（两级聚合拆独立连接并行 / hourly 节流）。
- **B9 无回执自动停机未实现**（与旧版对齐）。
- **微信 production 全凭据未实测**。

## 七、快速上手（起床后三条命令）

```bash
cd docker && cp .env.example .env   # 填密码与 JWT_SECRET
docker compose -f compose.prod.yaml --env-file .env up -d --build
scripts/ops/compose-smoke.sh        # 18 项冒烟自检
```

后台地址 http://127.0.0.1:8080/admin/（引导账号见 `.env`），H5 http://127.0.0.1:8080/h5/，设备口 9100/TCP。

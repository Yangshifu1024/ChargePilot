# Domain Docs

工程类技能在探索本仓库代码时应如何消费领域文档。

## 探索前先读

- 仓库根目录的 **`GLOSSARY.md`**（尚不存在则静默跳过，不要提示补建；`/domain-modeling` 技能会在术语真正落定时惰性创建）
- **`docs/adr/`**：阅读与即将动手的领域相关的架构决策记录，索引见 [docs/adr/README.md](../adr/README.md)。已有决策包括：单库合并、事件驱动与状态机、号段 ID、契约边界、容量边界

## 文件结构

单上下文仓库（本仓库即此形态）：

```text
/
├── GLOSSARY.md
├── docs/
│   ├── rewrite-plan.md
│   ├── adr/
│   └── agents/
└── backend/
```

## 使用术语表的词汇

输出涉及领域概念时（议题标题、重构提案、假设、测试命名），使用 `GLOSSARY.md` 定义的术语；不要漂移到术语表明确避免的同义词。

如果所需概念尚不在术语表中，这是一个信号：要么你在发明项目不用的语言（请重新考虑），要么存在真实缺口（记录下来交给 `/domain-modeling` 处理）。

## 标记 ADR 冲突

如果你的产出与既有 ADR 矛盾，显式指出而不是静默覆盖，例如：

> 与 ADR-002（事件驱动与状态机）矛盾，但值得重开讨论，因为……
